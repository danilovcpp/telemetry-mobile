# Telemetry Mobile

.NET 10 MAUI приложение для мониторинга устройств через Mobile API.

На Login введите **customerId 1–10** и любой пароль (можно оставить пустым). Приложение проверяет наличие клиента запросом к серверу, сохраняет только customerId в локальных Preferences и восстанавливает выбранного клиента после перезапуска. «Выйти» в меню устройств очищает сохранённый ID и возвращает Login. Авторизация в этом MVP отсутствует; пароль не отправляется и не сохраняется.

Данные загружаются с **http://api.konstek.de/** по контракту [mobile-api.md](docs/mobile-api.md) / [OpenAPI](docs/mobile-api.openapi.json):

- «Устройства» — список выбранного клиента, поиск по имени или deviceCode, переход в карточку.
- Карточка — код устройства, последний известный статус с датой и три последних события; «Все» открывает историю этого устройства.
- «События» — общая лента устройств клиента, новые сверху. Кнопка «Загрузить ещё» получает следующие страницы по отдельному курсору каждого устройства; события объединяются по времени и ID без пропусков на границах страниц.
- На экранах есть обновление кнопкой и pull-to-refresh, состояния загрузки, пустого результата и ошибки. Обновление истории заменяет загруженные страницы; повреждённый курсор сбрасывается. Время отображается в локальном часовом поясе.

API не сообщает онлайн/офлайн, IP, модель, версию ПО или фиксированные метрики, поэтому эти демонстрационные значения убраны. Числовые коды статусов отображаются без предположений об их значении. HTTP разрешён на Android/iOS/MacCatalyst только для домена api.konstek.de, включая демонстрационные Release-сборки. При переходе сервера на HTTPS измените TelemetryApiClient.BaseAddress и удалите доменные HTTP-исключения.

Поддерживаются светлая/тёмная темы и RU/EN/DE. Дизайн-система описана в [STYLE_GUIDE.md](TelemetryMobile/docs/design/STYLE_GUIDE.md).

```powershell
pwsh -File scripts/Validate-DesignSystem.ps1
dotnet build TelemetryMobile/TelemetryMobile.csproj -f net10.0-android
dotnet run --project tests/TelemetryMobile.SmokeTests
# Отдельная проверка доступного сервера; только GET, без изменения данных:
dotnet run --project tests/TelemetryMobile.SmokeTests -- --live
```

Smoke-тесты проверяют настоящий HTTP-клиент и page models с контролируемыми HTTP-ответами: сохранение ID, произвольный пароль, смену клиента, поиск, навигацию, null/JSON/UTC, обработку ошибок, отмену, пагинацию и общую сортировку событий. `--live` проверяет тот же клиент на реальном сервере для клиентов 1 и 10.

Debug-каталог компонентов запускается только при явном `-p:DesignSystemShowcase=true` и исключён из Release. Для самостоятельной установки Debug APK через adb добавьте `-p:EmbedAssembliesIntoApk=true` и нужный RuntimeIdentifier; обычный Debug использует Fast Deployment из IDE.
